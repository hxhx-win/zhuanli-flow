# 专利 DOCX 输出格式

本文件记录导出脚本的设计意图、官方表格对齐口径和公式源约束。版式参数、结构转换、校验清单均已由脚本实现并自动验证，不再重复列出。

## 参考基准

- 国家知识产权局官方表格：`cn-patent-rules/100001权利要求书.doc`、`100002说明书.docx`、`100003说明书附图.docx`、`100004说明书摘要.docx`
- `assets/reference.docx`（cn-patent-draft-v4.docx）作为历史样式参考，不再作为页边距权威来源
- 脚本采用的官方参数：A4 页面、页边距 top=1418/left=1418/right=850/bottom=850、宋体+Times New Roman、14pt、行距 360、首行缩进 200、两端对齐；页眉采用官方表格样式，黑体、加粗、14pt、居中、使用 Word 字符间距而不是空格拉开字距、无下边线
- 导出后验证对正文段落格式采用严格校验，首行缩进缺失或不一致时判定为 FAIL
- 每个官方模块 section 均设置居中页脚页码，并从 1 重新编号

## 公式源约束（给起草 agent 的）

导出脚本只消费已经规范的公式源：
- 独立公式来自 `latex` 代码块
- 段内公式来自 `\(...\)` 或 `$...$`
- 求和公式必须显式包裹主体，如 `\sum_{k=1}^{m}{x_{jk}}`
- 不要写成 `\sum_{k=1}^{m}x_{jk}` 并期待导出脚本猜测主体
- 源稿中仍有 `sum(...)`、`sqrt(...)`、`mu(θ)` 等伪公式文本时，应停止导出并退回起草流程修正

## 单文件与分片稿

默认输出一份完整查看稿，顺序为说明书摘要、摘要附图、权利要求书、说明书、说明书附图。完整查看稿便于研发、代理师和内部评审连续阅读。

当传入 `--split-output-dir` 时，导出脚本在完整稿生成后额外生成官方模块分片稿：

- `说明书摘要.docx`（包含摘要正文和摘要附图内容）
- `权利要求书.docx`
- `说明书.docx`
- `说明书附图.docx`（存在附图时）

分片稿复用同一套官方页边距、页眉、页脚页码和段落格式。分片稿用于后续人工整理提交材料，不包含请求书等电子申请系统表单。

## 取舍说明

本 skill 面向“单文件预提交稿 + 可选分片稿”输出，尽量对齐国家知识产权局四类官方表格的文档格式。它仍不负责请求书、费用减缴、著录项目等电子申请系统表单。优先满足：结构正确、文本完整、官方页边距和页码规则、权利要求与说明书对应、Word 中可继续人工编辑。
