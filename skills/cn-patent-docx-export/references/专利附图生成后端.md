# 专利附图生成后端

起草阶段必须基于已确认正式稿和证据来源先生成 `figure-generation-plan.md` 与 `figure-manifest.json`，明确每张图的图号、图名、技术内容、证据来源、推荐后端、后端专用字段和预期图片路径。DOCX 导出前，`cn-patent-docx-export` 主 agent 只按这两个结构化文件派子 agent 生成或复制图片资产，不得仅凭附图说明、摘要附图建议或说明书正文自由推断新增附图内容。

`new-patent-drawing-assets.py` 只能作为 manifest 校验、路径规范化和执行记录工具使用，不调用 mmdc，不调用任何绘图 skill。若缺少 plan/manifest、关键字段不足或必需图片缺失，应停止导出，除非用户明确授权缺图或无图 DOCX。manifest 中的 `preferredBackend` / `primarySkill` 是导出前派发子 agent 的约束，不是重新发明附图内容的提示。

## 多类型资产管线（执行原则）

- **流程 / 步骤 / 模块关系图**：Mermaid 子 agent 使用 `markdown-mermaid-writing` 和 mmdc 生成 PNG，保留 `.mmd` 源以便复核与修改；必须使用 [mermaid-patent-theme.json](mermaid-patent-theme.json) 渲染，不得使用 Mermaid 默认彩色主题。
- **系统结构 / 机械结构 / 路径姿态类示意图**：schematics 子 agent 使用 `scientific-schematics` 生成 PNG/SVG，并保留 prompt、审查记录与来源说明。
- **实验曲线 / 误差 / 对比图**：数据图子 agent 使用 `scientific-visualization`，按需调用 matplotlib / seaborn，保留原始 CSV/JSON 数据与绘图脚本。
- **外观 / 场景 / 说明性位图**：仅当用户明确授权时，image 子 agent 使用 `generate-image`；必须在 `figure-generation-plan.md` 或配套说明中标注**不宜单独作为权利要求支撑证据**，避免与可复核技术附图混用。
- **已有项目图片**：登记来源、规范命名后复制到附图输出目录并纳入 manifest，直接嵌入 DOCX，不擅自重绘或篡改技术内容。

## 后端选择表

| 附图类型 | 优先后端 | 适用说明 |
| --- | --- | --- |
| 方法流程、步骤链路、模块关系 | `mermaid-mmdc` | 可追踪、可修改，适合流程图 |
| 系统结构、机械结构、路径/姿态示意 | `scientific-schematics` | 不容易用 Mermaid 表达的技术示意图 |
| 数据曲线、误差曲线、实验对比 | `scientific-visualization` | 需数值可复核；常配合 matplotlib/seaborn，保留数据与脚本 |
| 说明性位图、外观类 | `imagegen` | 仅在用户授权时使用；与权利要求支撑证据区分标注 |
| 仓库已有示意图/照片（用户指定） | `existing-asset`（人工登记） | 复制与命名规范化后写入 manifest，不自动「再生成」 |

## Manifest 字段要求

公共字段：`figureNumber`、`caption`、`figureType`、`preferredBackend`、`primarySkill`、`imagePath`、`evidenceSource`、`generationStatus`。

导出脚本只将 `figureNumber` 放在图片正下方居中显示，不输出图名。附图总数在两幅以上时，`figureNumber` 必须为“图N”或阿拉伯数字 N，例如“图1”或“1”；只有一幅图时可以不编号。`caption` 仅用于附图说明、计划和人工识别。图片文件内部不得包含图号和图名。

后端专用字段：

- Mermaid：`mermaidPath`、`mermaidSource` 或 `sourcePath`、`themeConfigPath`、`renderCommand`。`themeConfigPath` 必须指向 `cn-patent-docx-export/references/mermaid-patent-theme.json`，`renderCommand` 必须包含 `mmdc -c <themeConfigPath> -b white`。
- scientific-visualization：`dataPath`、`plotSpec`、`scriptPath`、`stylePreset`、`outputFormats`。
- matplotlib：`dataPath`、`scriptPath`、`plotType`、`axisLabels`、`stylePreset`。
- seaborn：`dataPath`、`scriptPath`、`plotType`、`semanticMapping`、`stylePreset`。
- scientific-schematics：`prompt` 或 `promptPath`、`technicalConstraints`、`reviewLogPath`。
- generate-image/imagegen：`userAuthorization`、`prompt` 或 `promptPath`、`nonEvidenceNotice`。
- existing-asset：`sourceAssetPath`、`licenseOrSourceNote`、`copyTo`。

`generationStatus` 可取：`planned`、`generated`、`missing`、`skipped-with-authorization`、`existing-asset`。除 `skipped-with-authorization` 外，进入 DOCX 导出前 `imagePath` 必须存在。

## 专利风格硬约束

- 黑白或浅灰线框，白底，线条清晰，结构规整
- 无照片质感、无营销海报、无装饰背景、无渐变、无阴影、无卡通元素
- 中文标注简洁，使用 `步骤S1`、部件编号或模块名称
- 图片内不得包含图号和图名（如"图1 xxx"）；图号图名由说明书附图章节文字标注，图片本身只展示技术内容
- 只表达正式稿已有技术内容，不新增技术特征
- 多图之间保持同一线宽、字体、箭头样式

## Mermaid 流程图硬约束

Mermaid 流程图必须使用 `mermaid-patent-theme.json` 和白底参数渲染。推荐命令格式：

```bash
mmdc -i <input.mmd> -o <output.png> -c cn-patent-docx-export/references/mermaid-patent-theme.json -b white
```

Mermaid 源不得包含 `theme: default`、`theme: forest`、`theme: dark`、`theme: neutral` 或自定义彩色 `themeVariables`。确需局部强调时，只能使用黑色、白色或浅灰色，并保持线框图风格。

## 附图生成后清理

附图生成并通过 `--figure-manifest` 嵌入 DOCX 后，导出脚本应从正式稿中删除"附图交接清单"表格（以 `附图交接清单：` 开头到下一个 `##` 标题之间的内容）。该表格、`figure-generation-plan.md` 和 `figure-manifest.json` 均由起草 skill 生成，是起草 skill 与导出 skill 之间的机器交接中间产物，不应出现在最终 DOCX 中。

## 何时不用 AI 图像生成

- 已有 Mermaid、数据表或确定几何关系足以生成附图时
- 涉及权利要求范围、保护客体、关键算法步骤时，优先文本源或可复核绘图
- 未配置 API key 或生成结果不可复核时，导出阶段只保留起草阶段的 `figure-generation-plan.md` 和待人工绘图清单，不得改写图的技术内容
