# 保护客体判型与单一路由

本文件只负责起草前的保护客体判型和 reference 路由。详细撰写规则按判型结果只读取一个细分 reference，不在通用起草规则中重复维护。

## 判型输入

判型时读取以下信息：

- `selected_protection_object`、`selected_mainline`、`claimable_invention_points`、`distinguishing_features`。
- `mainline-analysis.md` 中的保护客体初步判断、技术特征分层、主体归属和适合写入位置。
- 证据矩阵中的核心资料类型：代码、结构图、设计文档、实验数据、技术交底。

## 判型结果

| 类型 | 典型信号 | 必读 reference |
| --- | --- | --- |
| 方法类 | 核心在输入、处理步骤、条件判断、映射、输出、异常/回退路径；常规同时配置装置、电子设备、存储介质和系统保护 | `method-claim-drafting.md` |
| 多主体方法 | 涉及第一设备/第二设备、端云、发送端/接收端、请求方/响应方 | `method-claim-drafting.md` |
| 结构类 | 核心在部件、连接、位置、投影、运动、尺寸/比例、材料或装配 | `structural-claim-drafting.md` |

## 主导发明点判定

同时出现方法流程、实体结构、设备、系统或介质信号时，不建立额外模板，而是按主导发明点单一路由：

- 方法/软件主导：创造性主要来自流程、判定、映射、通信、数据处理、系统协同或异常/回退路径，读取 `method-claim-drafting.md`。
- 结构/硬件主导：创造性主要来自部件组合、连接关系、空间/投影/运动关系、材料/尺寸配合或机械、光学、电气结构，读取 `structural-claim-drafting.md`。即使同时包含设备、控制方法、装配方法或软件控制逻辑，也按结构类主导处理。
- 双主线：结构特征和方法/系统特征各自都有独立区别特征时，不得拼装多个模板；应记录待确认事项，提示考虑分案或回到 Gate A 明确主线。

## 路由规则

1. 先确定主独权保护客体，判型后只读取一个细分 reference。
2. 方法类的常规配套装置、电子设备、存储介质和系统保护仍归入 `method-claim-drafting.md`，不得因此另设模板。
3. 机械结构为主体的混合方案，设备、控制方法、检测方法或介质仅作为配套保护时，读取结构类模板。
4. 单纯介质保护通常作为方法类兜底保护处理，读取 `method-claim-drafting.md`；除非用户明确要求独立介质稿，否则不单独判型。
5. 同时出现方法流程、实体结构或系统协同信号时，必须先按主要区别特征选择方法或结构主导模板；无法确定主导保护客体时，不得拼装多个模板，应记录待确认事项或回到 Gate A。
6. 若 `selected_protection_object` 已由 Gate A 确认，以 Gate A 为准；判型只决定读取哪个 reference 和如何落位。
7. 若发现主线与保护客体不匹配，不得自行换主线；应记录待确认事项或回到 Gate A。

## 快速检查

- 方法类不要写成模块堆砌，应有输入、步骤、条件和输出；其配套装置/设备/介质不改变方法类路由。
- 结构类不要写成流程步骤，应有部件、关系和约束。
- 系统、装置、电子设备和存储介质通常作为方法类配套保护，不单独触发模板路由。
- 介质权利要求通常引用方法权利要求，不单独扩展技术细节。
- 同时出现多类信号时，先判断主要区别特征；结构主导按结构类，方法或系统协同主导按方法类，双主线则回到 Gate A 或考虑分案。
