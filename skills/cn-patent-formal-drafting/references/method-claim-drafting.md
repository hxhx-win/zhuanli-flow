# 方法类和多主体方法起草规则

当 `claim-type-classification.md` 判定为方法类、多主体方法、方法+装置+介质组合保护时读取本文件。

若实体部件、空间关系、连接关系、运动关系、材料或尺寸配合才是区别特征，应改读 `structural-claim-drafting.md`。方法类覆盖装置、系统、电子设备、存储介质作为方法主线配套保护的情况。

## 适用范围与子类锚定

本文件以 CN113596424A（动态范围映射的方法和装置）作为参数算法子类的锚样稿，覆盖方法类细分中最常见的「参数算法 / 信号映射 / 控制策略 / 数据处理」类发明，含装置 / 电子设备 / 介质 / 系统配套保护。区别特征落在参数关系 / 公式 / 阈值 / 触发条件 / 连续性约束 / 数据结构定义之一时按本文件起草。

不适用：

- 结构主导方案 → [structural-claim-drafting.md](structural-claim-drafting.md)
- 多主体协议方案 → 本文件末 §多主体方法（无样稿对照，骨架仅作占位，待样稿补入后按 CN113596424A 同模式重写）
- 纯界面交互方案 → 不在本 skill 处理范围

阅读顺序（建议）：§独权骨架 → §从权梯队 → §红线 → §权要句式库 → §摘要 → §说明书各段 → §实施方式句式库 → §配套保护。多主体场景从 §多主体方法 入。每段都给「骨架 + verbatim 例句 + 要点 + 禁项」四部分；verbatim 例句皆引 CN113596424A，撰写时按句式选用，不套用任何泛化占位框架（占位符如 `【方法 A】【中间结果 1】` 出现即视为不合格）。

## 独权骨架

主题命名：`一种 + 发明名称`（发明名称为动词性短语，如「动态范围映射的方法」、「色调映射的方法」、「数据补偿的方法」）。

骨架行：`一种{发明名称}，其特征在于，包括：` 后接 4-6 个动作，分号分隔，末动作句号收尾。

CN113596424A 实证（权 1）：5 个动作 = 3 个「获取 + N」 + 1 个「在 X 成立时根据 A、B、C 得到 Y（含输出约束）」 + 1 个「根据 Y 对 Z 进行 W」。

动作分类与动词级别：

| 动作位 | 动词级别 | CN113596424A 权 1 实证 |
|---|---|---|
| 输入获取 | 获取 / 接收 / 采集 | 获取终端设备的显示参数；获取图像数据的特征信息；获取所述图像数据的第一色调映射曲线的第一参数 |
| 触发条件下处理 | 在 X 成立时，根据 A、B 和 C，得到 Y | 在预设条件成立时，根据所述第一参数、所述终端设备的显示参数和所述图像数据的特征信息，得到第二色调映射曲线的第二参数 |
| 输出动作 | 根据 Y 对 Z 进行 W / 输出 / 进入目标状态 | 根据所述第二色调映射曲线的第二参数对所述图像数据进行动态范围映射 |

输出约束句（可选）：触发条件下处理动作可在末尾内嵌「其中，{对象 Y}{约束}」一句，仅声明性约束，不引公式不引变量符号。CN113596424A 权 1 实证：

> 其中，所述第二色调映射曲线上第一点处的输出亮度不高于所述第二色调映射曲线上的所述第一点的输入亮度

动作数硬约束：4-6 个；< 4 个独权过抽象、保护边界不清；> 6 个独权过肥、违反独权肥度红线 R1。

## 从权梯队

按句式类型分 6 组（与 §权要句式库 A2 / A4 / A5 / A6 / A7 / A8 对应）；同一发明不需要每组都出，但 A5 + A6 + A7 + A8 至少出现一组以覆盖参数 / 公式 / 约束 / 装置维度。

| 分组 | 句式 | 引用方式 | CN113596424A 实证（共 24 条权要）| 典型场景 |
|---|---|---|---|---|
| A4 多分支条件 | `符合下列任意之一的条件时，则{结论}：{分支 1}；或者{分支 2}；或者…` | 单引用基权要 | 权 2（4 分支，引权 1）| 独权「在 X 成立时」的 X 展开 |
| A5 参数定义 / 其中展开 | `所述{对象}包括{子 A}、{子 B}；所述{子 A}包括{细化 1}和{细化 2}` | 单引用 / 二选一 / N 选一 | 权 3（引权 1 或 2）、权 4（引权 1-3 任意之一）、权 6（引权 1-5 任意之一）、权 12（引权 1-11 任意之一） | 参数 / 数据结构 / 处理路径展开 |
| A2 + A5 复合（处理路径展开）| 「其中{动作}包括：根据 X 和 Y，对 Z 进行调整」 | 同 A5 | 权 4 内嵌处理路径展开 | 独权动作内部展开 |
| A6 公式约束 | `所述{对象组}满足以下公式：{公式}其中，{符号}为{含义}…` | 引含展开的从权 | 权 5（引权 4）、权 7-8（引权 6，两公式以「或者」串）| 参数计算关系 / 多公式 |
| A7 连续性约束 | `所述 A 在 P 处的 Q1 与所述 B 在 P' 处的 Q1 相同，且…在…处的 Q2 与…相同` | 单 / 二选一 / N 选一 | 权 9（引权 8）、权 10（引权 8 或 9）、权 11（引权 8-10 任意之一）| 曲线衔接 / 信号匹配 / 空间约束 |
| A8 装置 / 介质 / 设备镜像 | 方法权要 N → 装置权要 (N + 方法总数)，单元粒度 ≤ 3 | 镜像方法权要 | 权 13-24（镜像权 1-12，3 单元：获取 / 处理 / 映射） | 配套保护 |

引用方式选用：单引用「权 N」表示该从权强制承继 N 的全部限定；「权 N 或 M」表示择一承继；「权 N-M 任意之一」表示在该区间任承继（CN113596424A 偏好用此式延展从权梯队）。

公式触发判断按 [formula-and-math.md](formula-and-math.md)；公式入从权采用 A6 句式，入实施方式采用 B3 句式（见 §实施方式句式库）。

## 红线

独权肥度防线 7 条（R1-R7），均针对**方法独权**（装置 / 介质 / 设备独权骨架见 §配套保护 + §权要句式库 A8）。任一违反 → 必须下放从权 / 实施例 / 分案。

R1 独权动作数 ≤ 6。CN113596424A 权 1 为 5 动作；超过 6 个 → 早绑实现风险，把工程粒度强行抬到独权层级。

R2 独权内不嵌：公式 / 变量定义 / 阈值具体数字。CN113596424A 权 1 无 `Tp / Ta / Tap` 阈值（这些进权 2 的 A4 多分支），无 `m_a, m_b, k1, k2` 等公式符号（进权 5 的 A6 公式）。

R3 独权内不嵌：步骤号 S1 / S2 / 步骤一 / 流程节点编号；不嵌伪代码 / 流程图节点引用。CN113596424A 权 1 全文无 S1 / S2 / 步骤字样。

R4 独权内不嵌：代码符号（函数名 / 变量名 / 文件名 / 类名 / 字段名 / 枚举常量名）。CN113596424A 权 1 用语义概念「显示参数」、「特征信息」、「第一参数」、「第二参数」、「第一色调映射曲线」、「第二色调映射曲线」，不出现 `MaxDisplay / max_lum / TH3[0] / MB[0][0]` 等具体符号；具体符号在权 4 + 权 5 中通过 A5 + A6 引入。

R5 独权内不嵌：连续性约束 / 衔接条件。CN113596424A 权 9-11 的 A7 连续性约束（一阶导数相同、Y 坐标相同）全部下放从权。

R6 独权内不嵌：装置单元名 / 模块名 / 处理器 / 存储器 / 通信模块。配套装置 / 介质 / 设备保护通过 A8 镜像在独立权要中实现。

R7 独权内不嵌：多分支条件的展开。「在 X 成立时」中 X 仅作为名词性短语出现；X 的展开（"符合下列任意之一…"）必须下放 A4 从权。CN113596424A 权 1 用「在预设条件成立时」，权 2 用 A4 展开预设条件的 4 个或者分支。

## 权要句式库

8 类权要句式（A1-A8）。骨架 + verbatim 例句 + 要点 + 禁项四段格式；例句皆引 CN113596424A。

#### A1 独权开头

骨架：`一种{发明名称}，其特征在于，包括：{动作 1}；{动作 2}；…；{动作 N}。`

例句（CN113596424A 权 1）：

> 一种动态范围映射的方法，其特征在于，包括：获取终端设备的显示参数；获取图像数据的特征信息；获取所述图像数据的第一色调映射曲线的第一参数；在预设条件成立时…

要点：主题命名 = 一种 + 发明名称（动词性短语）；「其特征在于」是定式；动作之间分号分隔，末动作句号收尾；动词级别用「获取 / 得到 / 在…时根据…得到 / 根据…对…进行…」。

禁项：动作内部嵌套连续性约束 / 公式 / 具体字段定义；步骤号 S1 / S2 入权要。

#### A2 条件触发

骨架：`在{条件}时，根据{依据 1}、{依据 2}和{依据 N}，{动作}`

例句（CN113596424A 权 1）：

> 在预设条件成立时，根据所述第一参数、所述终端设备的显示参数和所述图像数据的特征信息，得到第二色调映射曲线的第二参数

要点：用「在 X 成立时」，**不**用「基于 X」或「响应于 X」；多依据并列用「A、B 和 C」；条件本身的展开放到独立从权（A4）。

禁项：条件 X 在独权内展开为多分支；依据列表超过 4 项；用「基于 / 响应于 / 当…时…则…」替换「在…时…」。

#### A3 从权引用

骨架：`根据权利要求 {N}所述的{主题}，其特征在于，{附加技术特征}。`

例句（CN113596424A）：

> 单引用：根据权利要求 1 所述的方法（权 2）
> 二选一：根据权利要求 1 或 2 所述的方法（权 3）
> 多任选：根据权利要求 1-3 任意之一所述的方法（权 4）

要点：必须有「其特征在于」；引用方式三档（单 / 二选一 / 多任选）按从权颗粒度选用；CN113596424A 偏好「权 N-M 任意之一」以延展从权梯队。

禁项：用「进一步地，方法还包括」替代「其特征在于」；省略「所述的方法」中的「方法」字。

#### A4 多分支条件

骨架：

```
符合下列任意之一的条件时，则{结论}：
{分支 1}；
或者{分支 2}；
或者{分支 3}。
```

例句(CN113596424A 权 2)：

> 符合下列任意之一的条件时，则所述预设条件成立：根据所述第一参数对于图像数据进行色调映射时，所述第一色调映射曲线上第二点处的输出亮度高于所述第一色调映射曲线上的所述第二点处的输入亮度；或者所述第一参数中的参数 pP1 大于第一值 Tp，其中，所述第一值 Tp 是根据所述第一参数中的 aP1，以及预设的 aP1 与 pP1 的对应关系获得的；或者所述第一参数中的参数 aP1 大于第二值 Ta…；或者所述第一参数中的参数 aP1 与参数 pP1 的乘积大于第三值 Tap…

要点：首分支不带「或者」，第二之后均以「或者」领起；每分支可用「其中」内嵌辅助定义；条件结论用「则」连接。

禁项：分支之间用顿号或逗号分隔；首分支也加「或者」；分支展开过深（每分支应能单句收敛）。

#### A5 其中展开

骨架：`所述{对象}包括{子 A}、{子 B}；所述{子 A}包括{细化 1}和{细化 2}；所述{子 B}包括…`

例句（CN113596424A 权 4）：

> 所述第一参数包括第二一次样条曲线参数，所述第二一次样条曲线参数包括所述第一色调映射曲线中的第二一次样条的斜率 MB_mid[0][0] 和所述第二一次样条的区间像素点的亮度值的最大值 TH3_mid[0]，所述显示参数包括所述终端设备的最大显示亮度 MaxDisplay，所述特征信息包括所述图像数据的最大亮度校正值 max_lum

要点：多层嵌套展开，每新概念用「**所述**」引用前文，分号 / 逗号分隔多个并列展开；这是参数定义的核心句式；可在末尾用「其中，{动作}包括：…」内嵌处理路径展开（A2 + A5 复合）。

禁项：用「其中包含 / 其中含有」替代「所述 X 包括」；用「比如 / 例如」引出参数（这些是 B2 实施方式句式）；展开层次超过 3 层。

#### A6 公式说明

骨架：

```
所述{对象组}满足以下公式：
{公式}
其中，{符号 1}为{含义 1}，{符号 2}为{含义 2}，…
```

例句（CN113596424A 权 5）：

> 所述曲线参数 MB_mid[0][0] 和 TH3_mid[0]，以及所述曲线参数 MB[0][0] 和 TH3[0]，满足以下公式：…其中，L 为输入信号，G(L) 为色调映射曲线对应的函数 H(L) 的逆函数，m_a、m_b、m_m、m_n、k1、k2、k3 为曲线参数…

要点：定式「满足以下公式：」引出；公式独占行（用 latex 代码块按 [formula-and-math.md](formula-and-math.md) 写）；公式后立即「其中」+ 变量定义；每变量「{符号}为{含义}」或「{符号}表示{含义}」；多公式替代用「或者」串联。

禁项：公式跟动作挤在一段；变量定义省略或简写；公式后用「即 / 也就是」做等价化简而省略「其中」+ 完整变量清单；多公式之间用顿号分隔。

#### A7 连续性约束

骨架：`所述{对象 A}在{位置 P}处的{量 Q1}与所述{对象 B}在{位置 P'}处的{量 Q1}相同，且所述{对象 A}在{位置 P}处的{量 Q2}与所述{对象 B}在{位置 P'}处的{量 Q2}相同。`

例句（CN113596424A 权 9）：

> 所述第二色调映射曲线中的一次样条在 TH3[0] 处的 Y 坐标与所述第二色调映射曲线中的三次样条在 TH1[1] 处的 Y 坐标相同，且所述一次样条在 TH3[0] 处的一阶导数与所述三次样条在 TH1[1] 处的一阶导数相同。

要点：用「相同，且」而非「和」；适用于曲线衔接、信号匹配、空间约束；两个独立量分别对应；位置 P / P' 用具体阈值符号（TH3[0] / TH1[1] 等）引用前文 A5 段已定义的对象。

禁项：用「等于」替代「相同」；用「以及」替代「，且」；连续性约束直接入独权（违反红线 R5）；超过两组量并列（应拆为多条从权，CN113596424A 权 9-11 各表一组）。

#### A8 装置镜像

对应规则：方法权要 N → 装置权要 (N + 方法总数)，**逐条镜像**。

例句（CN113596424A 方法权要 1 → 装置权要 13）：

> （方法权 1）一种动态范围映射的方法…：获取终端设备的显示参数；获取图像数据的特征信息；获取所述图像数据的第一色调映射曲线的第一参数；在预设条件成立时…
>
> （装置权 13）一种动态范围映射的装置…：获取单元，用于获取终端设备的显示参数；所述获取单元还用于获取图像数据的特征信息；所述获取单元还用于获取所述图像数据的第一色调映射曲线的第一参数；处理单元，用于在预设条件成立时…；映射单元，用于根据所述第二色调映射曲线的第二参数对所述图像数据进行动态范围映射。

要点：方法动作 → 「{X}单元，用于{动作}」；同一单元承担多动作时第二动作起用「所述{X}单元还用于…」；从权 A6 公式 → 装置从权同一公式，措辞改「{Y}单元具体用于…」；单元粒度 ≤ 3（CN113596424A 用 3 单元：获取 / 处理 / 映射）。

禁项：装置权要扩展方法权要未覆盖的技术细节；用「模块」而非「单元」（CN113596424A 统一用「单元」）；单元粒度 > 4（过分拆解会让装置独权动作数膨胀，违反 R1 镜像约束）；装置权要不与方法权要严格 1:1（违反「逐条镜像」原则）；不分辨方法权要的实际动作就把 CN113596424A 实证的 3 单元划分（获取 / 处理 / 映射）直接套用到新发明上（装置单元必须按当前发明的方法独权动作语义重新归并，不得抄录样稿单元名）。

## 摘要

摘要回答四问：发明属于什么技术领域 / 解决什么问题、做了哪些核心动作、达到什么效果。文字部分不得超过 300 字。

骨架行：`本申请提供{发明名称}，有助于{效果回扣 / 避免的现有技术缺陷}。该{发明对象}，包括：{动作 1}；{动作 2}；…；{动作 N}。`

例句（CN113596424A 摘要 verbatim 节选）：

> 本申请提供了动态范围映射的方法和装置，有助于在图像的最大显示亮度与显示设备的最大显示亮度接近时，避免出现映射之后的终端设备的像素的亮度比原始的图像还要亮的异常现象。该动态范围映射的方法，包括：获取终端设备的显示参数；获取图像数据的特征信息；获取所述图像数据的第一色调映射曲线的第一参数；在预设条件成立时…根据所述第二色调映射曲线的第二参数对所述图像数据进行动态范围映射。

要点：以「本申请提供」领起；「有助于」开启效果回扣（呼应背景技术缺陷句）；动作列表与独权 A1 骨架同步、与权 1 verbatim 一致（不写「方法 A、方法 B、方法 C」占位）；摘要末以独权最后一个动作收尾，不再列从权 / 公式 / 阈值。

禁项：用「本发明属于【技术领域】，公开了一种【发明名称】」开头（属于占位骨架）；用「该方法包括【方法 A】、【方法 B】和【方法 C】」占位列表；用「显著 / 大幅 / 完美 / 革命性」夸张词；超过 300 字；堆公式 / 阈值 / 变量符号；只写做法不写效果；列从权梯队（从权应只在权利要求书与说明书出现）。

## 说明书

### 背景技术

背景技术建立问题场景，不提前介绍本发明方案。

骨架（4 段）：

1. 技术领域与基本概念（定义关键术语，给出 verbatim 单位 / 数值范围）
2. 应用场景与现有典型方案（指明现有方案类型 + 现有方案做法描述）
3. 现有方案适用范围（"在 X 情况下，可以采用方案 Y"，明示边界）
4. 共性矛盾与缺陷（"但是，在 X' 情况下，若仍使用上述方案，会导致…"，缺陷句一句直击发明内容要解决的问题）

例句（CN113596424A 背景技术 verbatim 节选）：

> 动态范围(dynamic range，DR)在很多领域用来表示某个变量的最大值和最小值的比率。在数字图像中，动态范围表征了在图像可显示范围内的最大亮度与最小亮度之间的比率，也就是图像从"最亮"到"最暗"之间灰度划分的等级数，其单位为坎德拉每平方米(cd/m2)，也可以表示为尼特(nits)。

> 现有技术中，在图像的最大亮度小于显示设备的最大显示亮度的情况下，可以采用基于"S"型曲线的动态范围的映射算法，将高动态范围图像调整到显示设备所能显示的动态范围内进行显示。

> 但是，在图像的最大亮度与显示设备的最大显示亮度接近的情况下，若果仍然使用上述方案，会导致映射之后的显示设备的像素的亮度比原始的图像还要亮的异常现象，影响用户体验。

要点：定义术语时给单位 + verbatim 等价表达（如 `cd/m2` 同时给 `nits`）；现有方案先指类型再描做法；用「在 X 情况下」+「但是…若仍使用」对比结构突出边界与缺陷；缺陷句单句收敛、直接对应发明内容要解决的问题（一致性闭环）。

禁项：「自【技术名称】出现以来…」泛化开头；「第一，【问题 1】；第二，【问题 2】；第三，【问题 3】」编号罗列（破坏问题间的因果链，CN113596424A 用「在 X 情况下…但是 X' 时…」对比直接给出，不编号）；提前出现「本发明 / 本申请实施例」字样（背景技术不介绍发明方案）；现有方案描述过弱或失真；只罗列文献不抽象共性矛盾；堆参数公式（参数公式进发明内容或实施方式）。

### 发明内容

发明内容按「方面 / 实现」逐方面展开。方面对应不同保护客体（方法 / 装置 / 电子设备 / 介质 / 程序产品），「在第 N 方面的一种可能的实现中」对应方面内的多个可选路径，与权利要求书的独权 + 从权梯队 verbatim 同步。

骨架：

```
第一方面，提供了{方法}，包括：
{动作 1}；
{动作 2}；
…
{动作 N}。

因此，本申请实施例通过{核心动作}，使得{中间结果}，从而有助于{解决的问题 / 避免的缺陷}。

在第一方面的一种可能的实现中，{从权 1 对应的细化}…

在第一方面的另一种可能的实现中，{从权 2 对应的细化}…

第二方面，提供了{装置}，包括：{获取单元，用于…}；{处理单元，用于…}；…

(第三方面 / 第四方面 / … 覆盖电子设备 / 介质 / 程序产品)
```

例句（CN113596424A 发明内容 verbatim 节选）：

> 第一方面，提供了一种动态范围映射的方法，包括：
> 获取终端设备的显示参数；
> 获取图像数据的特征信息；
> 获取所述图像数据的第一色调映射曲线的第一参数；
> 在预设条件成立时，根据所述第一参数、所述终端设备的显示参数和所述图像数据的特征信息，得到第二色调映射曲线的第二参数，其中，所述第二色调映射曲线上第一点处的输出亮度不高于所述第二色调映射曲线上的所述第一点的输入亮度；
> 根据所述第二色调映射曲线的第二参数对所述图像数据进行动态范围映射。
>
> 因此，本申请实施例通过对第一色调映射曲线的参数进行进一步的调整，使得调整后的曲线参数(即第二参数)对应的色调映射曲线(即第二色调映射曲线)上的某一点的输出亮度不高于该点对应的输入亮度，从而有助于在图像的最大显示亮度与显示设备的最大显示亮度接近时，避免出现映射之后的终端设备的像素的亮度比原始的图像还要亮的异常现象。

要点：

- 第一方面 = 方法（与独权 A1 骨架同步，动作列表逐字一致）
- 紧接「因此，本申请实施例通过…使得…从而有助于…」效果回扣段（与背景技术缺陷句呼应，闭环）
- 「在第一方面的一种可能的实现中」逐条对应方法的从权梯队（A4 / A5 / A6 / A7），描述与对应从权 verbatim 一致
- 第二方面对应装置（与 §配套保护 §装置权要 骨架同步，3 单元），后续方面覆盖电子设备 / 介质 / 程序产品
- 每方面结束后可加效果回扣段，但只回扣本方面新增的技术效果

禁项：

- 用「本发明解决上述技术问题所采用的技术方案是：…包括【方法 A】、【方法 B】、【方法 C】」（占位骨架）
- 用「首先【动作 1】；然后【动作 2】；最后【动作 3】」流水线语法（违反「方面 / 实现」组织，CN113596424A 不用此语法）
- 方面间编号丢失（不写「第一方面 / 第二方面」）
- 各方面动作列表不与权要书对应方权要 verbatim 一致（破坏权要书 ↔ 发明内容 ↔ 实施方式三方一致性）
- 效果回扣句脱离背景技术缺陷句（说效果但不闭环）
- 用「显著 / 大幅 / 完美」夸张词

### 附图说明

附图说明图号连续、图名统一；摘要附图优先选择最能说明关键技术关系的图（流程图 / 框图 / 关键示意图均可），图号与说明书附图一致。附图图片内除必要词语外不得有解释性注释；正文未提及的附图标记不得出现在附图中。附图交接按 [figure-handoff.md](figure-handoff.md) 处理。

例句（CN113596424A 附图说明 verbatim 节选）：

> 图1为PQ光电转移函数的图像。
> 图2为HLG光电转移函数的图像。
> 图3为SLF光电转移函数的图像。
> 图4为本申请实施例提供的高动态范围图像的动态范围调整曲线的示意图。

要点：图名格式「图 X 为 {对象 / 关系 / 示意图}」单句收敛；本申请提供的图加「本申请实施例提供的」前缀以区别于现有技术示意；图号顺序按"现有技术介绍图 → 本申请方法 / 装置 / 系统 / 流程图"分组。

禁项：图名超过 2 个分句；图内 Y/N、是 / 否 等判断字样进附图说明（应在具体实施方式描述）；正文未引用的附图标记出现在附图中；说明书与附图的图号不一致。

### 具体实施方式

方法类实施方式至少覆盖：

- 每个独权动作的输入、处理对象、条件判断和输出
- 关键从权的支撑段：参数定义（A5）、公式（A6）、连续性约束（A7）、多分支条件（A4）逐一展开
- 多主体方法中的消息方向、触发条件、响应结果和失败兜底
- 装置 / 电子设备 / 介质实施例中处理器、存储器、通信模块和程序指令的配合关系

实施方式按 §实施方式句式库 B1-B5 组织：B1 段落组织 / B2 参数取值 / B3 计算示例 / B4 可选实施方式 / B5 效果回扣。**不使用** S1 / S2 步骤号、`### 步骤一` 三级标题切分、`1. 2. 3.` 编号列表替代自然段。

开头建议（CN113596424A 实证）：

> 下面将结合附图，对本申请中的技术方案进行描述。

> 首先，对本申请实施例中涉及的相关概念和技术作简单介绍。

或：

> 参见图 1，本申请实施例提供{方法 / 装置 / 系统}的示意图…

实施方式不足时，按顺序补写：先补独权必要特征，再补重要从权支撑段，再补异常 / 回退 / 替代参数 / 替代结构，再补装置 / 系统 / 介质实施例，最后补附图标号对应和技术效果回扣。补写只能基于已确认主线、证据矩阵、检索后可主张发明点、用户授权假设和已有实施细节。

## 实施方式句式库

5 类实施方式句式（B1-B5）。骨架 + verbatim 例句 + 要点 + 禁项四段格式；例句皆引 CN113596424A 整理版 §具体实施方式 verbatim。

#### B1 段落组织

规则：每段一个完整逻辑单元；段间空行分隔；一段写一个动作 / 一段写一组定义 / 一段写一个示例 / 一段写一段效果回扣；一个动作的多步骤可在同一段内用句号串接，不强行拆段。

例句（CN113596424A 整理版）：

> 一些实施例中，在获取图像数据 V 的同时，还可以获取该图像数据的特征信息，例如从元数据 (metadata) M 中获取。其中，图像数据 V 的元数据 M 用于表示该图像数据的数据特征…

要点：段间用空行分隔，段内允许多句串接；新逻辑单元开新段；技术效果回扣单独成段。

禁项：步骤号 `步骤 S1，获取...；步骤 S2，基于...`；小标题滥用 `### 步骤一` / `### 实施例 1.1.1`；用 `1. 2. 3.` 编号列表替代自然段；参数取值 / 计算示例 / 可选实施方式不设小标题。

#### B2 参数取值段

骨架：`示例性的，{对象}例如可以为{值 1}或{值 2}，比如{具体形态}，本申请实施例对此不作限定。`

例句（CN113596424A 整理版 §具体实施方式）：

> 示例性的，第二参数 Rcurve 可以具有以下公式 (9) 所示的形态…

要点：定式「**示例性的**」领起；用「例如可以为 / 比如 / 等」给出多种参数候选；以「本申请实施例对此不作限定」收尾留扩展空间。

禁项：用「优选 / 优选地」（属于专利文本忌用词）；省略「示例性的」开头；省略「本申请实施例对此不作限定」收尾；用「必须 / 应当 / 一定」强约束词。

#### B3 计算示例段

骨架：动作段 → 公式独占段 → 变量定义段（三段连续，空行分隔）

例句（CN113596424A 整理版 §具体实施方式）：

> 可以根据以下公式 (10) 和 (11)，确定上述第一最大输入亮度 TH3C 和斜率 Dark…
>
> [此处按 [formula-and-math.md](formula-and-math.md) 写 latex 公式 (10)(11) 独占代码块]
>
> 其中，TH3C0 为第一初始最大输入亮度，Dark0 为初始斜率，MaxSource 为最大源亮度，WA、N1、N2 为预设参数…

要点：前段以全角「：」收尾引出公式；公式独占段（按 [formula-and-math.md](formula-and-math.md) 用 latex 代码块）；「其中」段把变量按「{符号}为{含义}」全部定义；编号公式用 (1) (2) (3) 圆括号格式。

禁项：公式跟动作挤在一段；公式后变量定义省略或简写；公式编号用 `[1] [2]` 方括号；公式独占段同时塞 2 个以上公式（多公式应分段，或用「以及」连接的同一组公式）。

#### B4 可选实施方式段

骨架：`一些实施例中，{替代方式 1}；或者{替代方式 2}，本申请实施例对此不作限定。`

例句（CN113596424A 整理版 §具体实施方式）：

> 在一些可选的实施例中，上述第二参数还包括一次样条曲线参数，该一次样条曲线参数包括该第二色调映射曲线中的一次样条 (可以记为第一一次样条) 的区间像素点的亮度值的最大值 TH3C…

要点：用「**一些实施例中**」或「**在一些可选的实施例中**」领起；多替代用「或者」串联；以「本申请实施例对此不作限定」收尾。

禁项：用「在另一种实施方式中」做 `### 小标题` 切分（小标题切分留给独立实施例）；用「优选」表达替代关系；省略「一些实施例中」开头。

#### B5 效果回扣段

骨架：`因此，本申请实施例通过{核心动作}，使得{中间结果}，从而有助于{解决的问题} / 避免{现有技术缺陷}。`

例句（CN113596424A 整理版 §具体实施方式）：

> 本申请实施例中，在根据第二参数对图像数据进行动态范围映射时，在图像数据的暗区可以使用该直线部分进行色调映射，这样可以控制亮度的增益，同时更方便控制第二参数从直线逐渐变化到 y=x 的直线…

要点：以「**因此**」或「**本申请实施例中**」领起；复述核心动作 + 中间结果 + 与背景技术呼应的「解决的问题 / 避免的缺陷」；可用「使得 / 从而 / 这样 / 同时」连接因果。

禁项：用「显著 / 大幅 / 完美 / 革命性 / 突破性 / 极大」等夸张词；用「优于现有所有方法 / 优于本领域所有方案」绝对化对比；省略对背景技术问题的呼应（效果回扣脱节）；只写效果不写产生效果的具体动作。

## 配套保护

方法类通常同时配置装置、电子设备和存储介质保护；这些配套保护按本节骨架，不另行读取系统 / 装置或介质 reference。

### 装置权要

装置权要按 §权要句式库 A8 装置镜像 规则起草：方法权要 N → 装置权要 (N + 方法总数)，单元粒度 ≤ 3（CN113596424A 实证用「获取单元 / 处理单元 / 映射单元」3 单元）。

例句（CN113596424A 权 13 verbatim）：

> 一种动态范围映射的装置，其特征在于，包括：获取单元，用于获取终端设备的显示参数；所述获取单元还用于获取图像数据的特征信息；所述获取单元还用于获取所述图像数据的第一色调映射曲线的第一参数；处理单元，用于在预设条件成立时，根据所述第一参数、所述终端设备的显示参数和所述图像数据的特征信息，得到第二色调映射曲线的第二参数，其中，所述第二色调映射曲线上第一点处的输出亮度不高于所述第二色调映射曲线上的所述第一点的输入亮度；映射单元，用于根据所述第二色调映射曲线的第二参数对所述图像数据进行动态范围映射。

要点：每个方法动作对应「{X}单元，用于{动作}」；同一单元承担多动作时第二动作起用「所述{X}单元还用于…」；从权 A6 公式 → 装置从权同一公式，措辞改「{Y}单元具体用于…」；命名统一用「单元」不用「模块」。

禁项：装置权要扩展方法权要未覆盖的技术细节；用「获取模块 / 处理模块 / 判定模块 / 输出模块」4 模块拆解（违反 CN113596424A 实证 3 单元 + R1 镜像约束）；用「模块」措辞（CN113596424A 统一用「单元」）；单元粒度 > 4；装置权要不与方法权要严格 1:1（违反「逐条镜像」原则）。

### 电子设备

通用骨架（行业标准，CN113596424A 未单出独立例句，作为方法 / 装置之外的兜底保护）：

```text
一种电子设备，包括处理器、存储器以及存储在所述存储器中并可在所述处理器上运行的程序指令，其特征在于，所述处理器执行所述程序指令时实现权利要求{方法权利要求编号}所述的方法。
```

要点：单引方法权要的全部技术内容，不重复展开；编号引用直接给方法权要号；若通信模块、采集模块、控制模块或执行机构本身参与区别特征，应在同一权要句框架内写清其与处理器、存储器或外部主体的配合关系，否则不扩展。

禁项：在电子设备权要中扩展方法权要未覆盖的技术细节（这些应进装置权要或实施方式）；省略「程序指令 / 处理器 / 存储器」三件套；用「模块」拆解电子设备硬件（电子设备权要的硬件描述以「处理器 + 存储器」为主，模块化拆解留给装置权要）。

### 存储介质

通用骨架：

```text
一种计算机可读存储介质，其上存储有程序指令，其特征在于，所述程序指令被处理器执行时实现权利要求{方法权利要求编号}所述的方法。
```

要点：存储介质权要单引方法权要，不单独扩展。需要限定存储介质形态（光盘 / U 盘 / 闪存 / 网络下载等）、程序分发方式或执行主体时，进实施方式。

禁项：存储介质权要扩展方法权要未覆盖的技术细节；省略「程序指令 / 处理器」描述；列具体介质形态（应进实施方式）。

## 多主体方法

> **本段无 CN113596424A 样稿对照**（CN113596424A 是单主体方法 + 装置），骨架作为占位保留；待多主体协议类样稿（端云协同 / 客户端-服务端 / 设备间通信等）补入后按 CN113596424A 同模式重写为 verbatim 锚定版。撰写时优先依据真实样稿，本段仅做最小骨架引导。

涉及两个以上执行主体时，不要把所有动作塞进一个主体的方法独权。先判断是否需要拆分：

- 第一主体方法：第一设备、发送端、请求方、客户端、采集端或控制端执行的步骤
- 第二主体方法：第二设备、接收端、响应方、服务端、显示端或执行端执行的步骤
- 系统权利要求：至少两个主体之间的协同关系、消息流和状态切换
- 电子设备 / 介质权利要求：处理器执行对应方法步骤

第一主体方法通常写：

```text
第一主体获取{输入 / 操作 / 状态}；
响应于{条件}，生成{指令 / 请求 / 数据}；
通过{通信链路 / 接口}发送至第二主体；
在{失败 / 占用 / 超时}时执行{本地回退}。
```

第二主体方法通常写：

```text
第二主体接收来自第一主体的{指令 / 请求 / 数据}；
响应于{指令 / 状态}，执行{处理 / 显示 / 控制}；
生成{反馈 / 应答 / 结果}并返回或进入{目标状态}。
```

系统权利要求应写清主体之间的通信链路、职责分配和协同效果；不要只堆模块名。

## 独权设计支持

方法类独权保护输入、关键处理步骤、核心判定 / 映射关系和输出结果。独权只保留解决技术问题不可缺少的步骤，非必要的缓存、回退、格式适配、平台兼容、日志、告警和整机应用默认下放从权或实施例。

独权检查：主题明确，步骤完整；不写纯效果限定；不绑定软件名、文件名、脚本名、设备型号或消息名；不使用「如说明书所述」「如图所示」；每一步都能在说明书中展开。

必要性筛查：删除该特征后，是否仍能解决核心技术问题并体现区别特征；该特征是否只限定具体实现、部署环境、数据格式、缓存策略、回退策略、参数取值或整机应用；该特征是否会把保护范围锁死到当前代码实现、当前平台或当前产品形态。任一答案为"是"时，优先下放。

骨架选用引导：

- 命中参数算法子类（CN113596424A 锚样稿覆盖范围）→ 按 §独权骨架 + §从权梯队 + §红线 + §权要句式库 + §实施方式句式库 起草
- 涉及两个以上执行主体 → 按 §多主体方法 起草（待样稿补入后会有更精确的骨架）
- 非该子类且单主体的方法 → 按上述独权检查 + 必要性筛查 自行设计骨架，不套用任何泛化 4 步框架；必要时新建子类骨架（结构类样稿、协议类样稿到位后陆续补入）
