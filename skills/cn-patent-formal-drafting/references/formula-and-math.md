# 数学与公式优化

> Windows 原生环境：命令中的 `python3` 请用 `python` 或 `py` 代替。

本文件是正式稿中公式触发、公式写法和 DOCX-ready 公式源的唯一规则来源。其他起草规则可引用本文件，不应另设独立公式触发条件。

核心原则：公式用于限定保护边界、支撑区别特征、表达判定/映射/约束关系或承载可验证技术效果。能够更清楚表达技术边界的内容应采用公式或受控数学表达；用文字更清楚的流程、模块职责和实施说明可以采用文字描述。

每个公式的变量都要定义。每个目标函数要说明优化对象、输入、输出、约束关系。算法步骤若涉及优化、迭代或判定，必须说明初始化、求解、判定、终止和输出。数学特征必须挂靠到具体工程对象，不能把纯数学变换孤立成权利要求。

## 公式触发规则

### 必须公式化的场景

以下内容若进入权利要求、发明内容或具体实施方式，应优先用公式或受控数学表达限定：

- 参数范围或比例关系：焦距比、曲率半径比、波长比例、阈值范围、容量上限、字段长度、偏移量或尺寸关系。
- 映射关系：输入状态到输出模式、平台能力位到档位、设备状态到显示路径、字段组合到解析方式。
- 判定条件：触发回退、切换状态、选择模式、拒绝编译、淘汰缓存、确认有效数据的条件。
- 优化目标或约束：目标函数、代价函数、误差函数、距离、相似度、碰撞/干涉约束、连续性约束。
- 协议或数据结构边界：头部字段长度、载荷大小、偏移关系、队列容量、缓存上限、窗口长度。
- 可验证效果指标：误差、效率、时延、带宽、空间占用、隔离度、稳定性、成功率等有证据支撑的指标。

### 适合文字描述的场景

以下内容通常用文字更清楚：

- 普通顺序流程，例如获取、处理、输出。
- 模块职责描述，例如注册模块、处理模块、显示模块的常规功能。
- 代码机制的表面翻译，例如工厂构造、对象注册、容器插入、接口调用，除非其中的判定、映射或容量边界本身是区别特征。
- 没有变量定义、没有工程对象挂靠、没有技术作用说明的表达。
- 缺少证据支撑的量化效果或参数取值。

### 边界判断

不确定是否公式化时，按以下问题判断：

1. 该公式是否比文字更清楚地限定技术边界？
2. 该公式是否支撑区别特征、参数范围、判定条件、映射关系、优化目标或协议约束？
3. 该公式中的变量是否都能定义输入来源、物理/工程意义和输出用途？
4. 该公式是否能被说明书中的实施例或证据矩阵支撑？

若答案主要为“否”，应使用文字描述；若答案主要为“是”，应公式化并按本文件的 DOCX-ready 规则书写。

## DOCX-ready 公式源要求

正式稿交给 `cn-patent-docx-export` 前，必须先通过 LaTeX 公式源校验。该校验只判断公式源是否可被导出链路稳定消费，不负责改写技术方案。

生成正式稿时，公式源不是"普通可读 LaTeX"，而是面向 DOCX 导出的受控 LaTeX。原则是：作用域显式、变量文本化、函数名规范、乘法关系清楚、普通文字不伪装成公式。

### 1. 标记边界

- 独立展示公式写成 `latex` 代码块。
- 段内变量、函数和短公式写成 `\(...\)`。
- 普通中文说明保持普通文字；当确有必要表达等式、集合、约束、函数调用、范围或映射关系时，应进入 LaTeX 标记。

### 2. 作用域显式

对带有求和、乘积、积分等聚合含义的算子，必须显式包裹主体，避免 Word 公式解析时把主体误并入上下限。

```latex
\sum_{k=1}^{m}{x_{jk}}
\prod_{r=1}^{d}{p_r}
\int_{0}^{T}{v(t)\,dt}
```

不要写成：

```latex
\sum_{k=1}^{m}x_{jk}
```

对于最大值、最小值等选择函数，正式稿优先写成函数式或集合式表达，不使用上下限样式承载作用对象：

```latex
T_{\mathrm{max}}=\operatorname{max}(T_1,T_2,\ldots,T_m)
J_{\mathrm{min}}=\operatorname{min}(J_1,J_2,\ldots,J_n)
```

不要写成：

```latex
T_{\max}=\max_{k=1}^{m}T_k
```

### 3. 变量文本化

变量下标中的文字语义使用 `\mathrm{...}`，不要把 LaTeX 算子命令当成普通文本。

```latex
T_{\mathrm{max}}
d_{\mathrm{min}}
v_{\mathrm{max}}
\theta_{r,\mathrm{min}}
```

不要写成：

```latex
T_{\max}
d_{\min}
v_{\max}
\theta_{r,\min}
```

### 4. 函数名规范

工程函数、几何函数和自定义函数使用 `\operatorname{...}`，常见三角函数或标准 LaTeX 函数可保持原命令。

```latex
\operatorname{dist}(B_k(\theta_k),B_l(\theta_l))
\operatorname{angle}(z_{k,h},n_{k,h,\mathrm{ref}})
\operatorname{det}(J(\theta)J(\theta)^{\mathrm{T}})
```

### 5. 乘法和转置

权重、变量、矩阵乘积之间不要压缩到不可读的裸连接；需要强调乘法关系时使用 `\cdot` 或空格。转置使用 `^{\mathrm{T}}`。

```latex
J=w_t\cdot T_{\mathrm{max}}+w_d\cdot D_{\mathrm{switch}}
J(\theta)J(\theta)^{\mathrm{T}}
```

### 6. 禁止伪公式源

不得保留 `sum(k=1 to m)`、`sqrt(...)`、`mu(θ)`、`^T`、`||...||`、裸 `Jalloc=...`、`lambda1 sum(...)` 等伪公式写法。导出前运行：

```bash
python3 .agents/skills/cn-patent-workflow-orchestrator/scripts/test-latex-formula-readiness.py --draft-path patent/<patent-slug>/drafts/markdown/<draft-name>.md --fail-on-error
```

## 必须完成的动作

### 1. 变量定义

对所有公式中的变量逐一定义：

- 物理意义
- 几何意义
- 所属步骤
- 输入来源
- 输出作用

### 2. 目标函数定义

明确：

- 优化变量是什么
- 目标函数最小化或最大化什么
- 该目标为何与技术效果相关
- 输出结果用于哪个后续步骤

### 3. 约束条件定义

尽量明确以下约束是否存在：


- 曲面贴合约束
- 步距或测地距离约束
- 角度、保角或方向约束
- 姿态可达性约束
- 碰撞或干涉约束
- 连续性约束
- 关节或轨迹约束

### 4. 求解流程定义

若涉及优化或迭代，必须交代：

- 初始值
- 迭代方式
- 判定条件
- 终止条件
- 输出内容

### 5. 工程挂靠

所有数学特征必须挂靠到实际工程对象，例如：

- 点云
- 路径点
- 曲面法向
- 打印喷头姿态
- 机械臂关节角
- 三角剖分约束区域
- 平面参考路径
- 曲面映射路径
- 轨迹时间参数化结果

## 禁止写法

避免以下空泛表述：

- 采用已知优化算法求解即可
- 由公式可知
- 通过数学模型优化得到最优结果

若使用这些表述，必须进一步解释变量、约束和工程意义。

## 输出建议

当用户需要公式时，优先输出：

- 公式框架
- 变量定义
- 目标函数分项含义
- 约束条件含义
- 求解流程位置

若用户没有要求具体数值，可保留符号级表达，不必强行写死参数。
