# 审查清单

本文件承载代理师审稿的细项检查标准。单 agent 模式下由主 agent 执行除气质审查以外的清单；气质审查始终由只读气质审查子 agent 执行。多 agent 模式下由对应只读子 agent 按章节读取并返回结构化发现，主 agent 只负责汇总、去重、处理冲突和分级。

所有清单均不得要求读取、抽取或加载 PDF。

## 通用输出字段

每个子 agent 返回发现时至少包含：

- `dimension`：气质、权利要求、说明书支撑、形式与证据、语言风格、法条合规。
- `location`：权利要求、说明书章节、摘要、附图说明、状态文件或导出契约。
- `issue`：具体问题，不写泛泛判断。
- `risk`：对保护范围、创造性、支撑充分性、清楚性或交付可用性的影响。
- `suggestion`：可执行修改方向。
- `priority_hint`：高 / 中 / 形式。
- `needs_user_decision`：是否需要用户选择、补证或授权。
- `article`（仅法条合规方向必填）：`22.2 | 22.3 | 22.4 | 26.3 | 26.4`。
- `defect_type`（仅法条合规方向必填）：`形式 | 逻辑`。

## 权利要求审查清单

输入文件：

- 待审专利稿的权利要求书。
- 编排模式下的 `patent-iteration-state.json`、`mainline-analysis.md`、`prior-art-search.md` 或等价检索后结论。
- 必要时读取 `cn-patent-formal-drafting/references/drafting-rules.md` 中独权必要性规则。

必须检查：

- 独权必要性：独立权利要求是否只保留解决核心技术问题不可缺少、且与区别特征和技术效果存在直接因果关系的必要特征。
- 非必要特征下放：若把完整工程链路、可选缓存、回退、平台适配、数据格式、异常处理、参数细化或整机应用写入独权，应列为中高优先级问题，并建议下放从权或实施方式。
- 从权梯度：从属权利要求是否按核心区别具体化、参数/关系限定、异常/回退、替代实施、保护客体扩展等层次展开。
- 重复和空泛：若从权只是重复独权、只写效果或只列模块名称，应要求重写。**并列独权之间、并列独权与从权之间字面/语义复刻**（如 P2 独权与 P1 间接从权对同一组特征逐字重写）必须单列为高优先级，与同根因 26.4 联动。
- 跨权要技术方案一致性：同一概念在不同权要中的实现细节是否冲突（例：互斥保护方式在权 X 表述为"锁外深拷贝"、在权 Y 表述为"锁内读+锁外拷+锁内校"）。命中即列高优先级，与同根因 26.4 联动。
- 保护范围：检查独权是否过窄、从权是否缺少可授权退路、并列独权是否彼此支撑。

优先级提示：

- 独权包含大量非必要实现细节，导致保护范围明显过窄，通常不低于中优先级；若影响核心保护，应列高优先级。
- 从权缺少梯度但独权尚可成立，通常列中优先级。

## 说明书支撑审查清单

输入文件：

- 待审专利稿的摘要、说明书、附图说明和权利要求书。
- evidence notes、实施方式覆盖计划或等价起草 notes。
- 编排模式下的 `claimable_invention_points`、`distinguishing_features` 和 `feature_layers`。

必须检查：

- 实施方式密度：是否存在实施方式覆盖计划；具体实施方式是否支撑每个独权必要特征和重要从权。
- 覆盖范围：是否包含可选实施方式、替代方案、异常/回退路径、附图标号对应和效果回扣。
- 特征支撑：每个独权必要特征是否有实施段落，重要从权是否有支撑段。
- 效果链条：实施细节是否形成“特征 -> 作用 -> 技术效果”链条。
- 发明内容对应：发明内容中的每个关键环节是否能在具体实施方式中找到展开，且没有只在发明内容中概括、实施方式中缺位。
- 附图支撑：结构类或包含装置结构的稿件是否有标号、部件关系和图文对应；方法类是否有步骤、主体、消息流或状态流图文对应。

优先级提示：

- 实施方式不足以支撑权利要求时，应列为高优先级问题。
- 缺少可选实施方式、替代方案或效果回扣但不影响独权支撑时，通常列中优先级。

## 形式与证据审查清单

输入文件：

- 待审专利稿。
- 编排模式下的状态文件、evidence notes、figure manifest、quality check 结果和 Gate 记录。
- `cn-patent-formal-drafting/references/formula-and-math.md`。

必须检查：

- 代码抽象：权利要求和说明书是否用函数名、变量名、类名、枚举常量名替代技术特征；代码标识符是否只在首次出现时作为括号辅助说明。
- 公式触发：应公式化的技术边界是否遗漏公式；普通流程、模块职责或代码注册/构造路径是否可用文字更清楚地表达。
- 证据边界：为补足实施方式密度而新增的参数、结构、效果或替代方案是否有证据、用户授权假设或明确待确认标记；无证据内容不得写成确定事实。
- 创造性一致性：正式稿是否围绕检索后确认的区别特征展开，权利要求、发明内容和实施方式是否偏离 Gate A 主线或削弱创造性论证。
- 导出契约：检查标题结构、内部章节残留、公式源格式、附图交接产物、`figure-manifest.json` 顶层结构和 DOCX 导出契约。

优先级提示：

- 无证据内容写成确定事实、偏离 Gate A 主线或削弱区别特征，通常列高优先级。
- 代码标识符较多、公式源格式不稳、内部备注残留，按影响列中优先级或形式与术语问题。

## 语言风格审查清单（B 风格硬规则）

输入文件：

- 待审专利稿（权利要求书 + 说明书）。
- `cn-patent-formal-drafting/references/language-style-guide.md`（7 条硬规则、差例重写、自检清单的唯一来源）。

主 agent 单 agent 模式下必须按本清单执行；多 agent 模式下并入「形式与证据审查」子 agent，或单独派发只读「语言风格审查」子 agent。

逐条核对（每命中一处必须输出一条 finding，不得汇总成一句概括）：

- **R1 句长拆短**：搜权要中逗号 ≥ 5 个且无分号的句子；搜单条特征句分号嵌套是否超过两层。命中即列高优先级或中优先级。
- **R2 自造术语括注**：列出全文自造词；核对每个自造词在权要首次出现处是否加引号或括号定义；同一概念是否同名同义。命中（自造词无定义、或同义异名）一般列中优先级；同义异名导致检索断裂列高优先级。
- **R3 禁目的句**：在权利要求书内全文搜 `以使`、`从而`、`以保证`、`以支持`、`避免`、`以便` 等目的性短语；命中处必须输出"删除该句、效果挪入发明内容"建议，列高优先级（涉及保护范围）。
- **R4 禁论证句**：搜权利要求书 + 发明内容段中 `不可分割`、`不能被分解`、`本领域技术人员据此` 等论证 / 自认窄表述；命中即列高优先级（此为"自认窄"风险）。
- **R5 缩写双注 + 公式符号定义**：列出全文缩写，核对首现处是否中英文双注；列出权要内出现的公式符号，核对所在权要或紧邻段是否有文字定义。命中列形式与术语问题或中优先级。
- **R6 八股段落**：搜发明内容段是否使用 `第一方面`、`第二方面` 等自创编号；现有技术段是否使用 `第一类是…第二类是…` 散文体。命中列中优先级，给出"改为'基于第 N 方面，在一种可能的实施方式中'或'在一种现有技术中…'"建议。
- **R7 代理腔**：搜实施方式段是否出现 `需要特别说明`、`核心精细时序设计之一`、`本设计避免了`、`并非可由本领域技术人员直接想到` 等强调或辩论语；公式渲染是否完整（搜文本中是否出现"其中, 为…"等明显符号缺失）。命中列中优先级；公式渲染缺失列高优先级（形式驳回风险）。

输出要求：

- 命中 R3 / R4 的条款必须单独列入「高优先级问题」；
- 命中 R1 / R2 / R6 的条款列入「中优先级问题」；
- 命中 R5 / R7 公式问题列入「高优先级问题」；其他 R5 / R7 列入「形式与术语问题」；
- 修改建议必须援引 `language-style-guide.md` 对应小节的差例重写示例，不得只给抽象描述。

优先级提示：

- 权要内出现 `以使` / `不可分割` 即视为保护范围风险，必须列高优先级。
- 自造词不加注、装置权与方法权语言风格不一致，列中优先级。
- 公式符号缺失、缩写未双注，列形式与术语问题；但公式整体在 docx 中无法渲染（图片或乱码）列高优先级。

**纪律**：审稿建议不得反向把 B 风格改回 A 风格；任何"保留高密度技术散文"或"保留'不可分割'论证"的建议视为违规。

## 法条合规审查清单（审查员视角）

输入文件：

- 待审专利稿。
- 编排模式下：`evidence/prior-art-search-report.md`（用于 22.2 / 22.3 比对锚点）。

子 agent 必须以**专利审查员视角**自检，按以下 5 法条逐条审，输出落盘 `reviews/attorney-review/06-legal-compliance.md`，每节列发现条目，每条含通用字段 + `article` + `defect_type`。

### 22.2 新颖性

触发场景：与 `prior-art-search-report.md` 中 `recommended_mainline` / `closest_prior_art` 的技术特征比对，本稿独权是否存在与对比文件实质相同的技术方案。

典型缺陷：

- 独权与最近现有技术特征完全对应，无任何区别特征 → 高，`article=22.2`，`defect_type=逻辑`
- 区别特征仅是惯用手段直接置换 → 中（同时 22.3 也会命中），`article=22.2`，`defect_type=逻辑`

严重度判定：是否会被审查员直接以 22.2 驳回。

### 22.3 创造性

触发场景：区别特征是否「非显而易见」；技术启示是否被对比文件给出；技术效果是否在区别特征实现且可验证。

典型缺陷：

- 区别特征仅参数范围调整且未论证「非常规」→ 中，`article=22.3`，`defect_type=逻辑`
- 技术效果在说明书中未量化、未实验数据支撑 → 中（同时 26.3 命中），`article=22.3`，`defect_type=逻辑`
- 区别特征对应的技术问题在背景技术段未明示 → 中，`article=22.3`，`defect_type=逻辑`

严重度判定：能否在通知书答复中找出至少 1 条非显而易见论据。

### 22.4 实用性

触发场景：方案是否能被制造 / 使用并产生积极效果。

典型缺陷：

- 方案违反自然规律 → 高，`article=22.4`，`defect_type=逻辑`
- 缺乏工业再现性（依赖偶然条件）→ 高，`article=22.4`，`defect_type=逻辑`
- 无技术效果或效果不可验证 → 中，`article=22.4`，`defect_type=逻辑`

严重度判定：审查员会否以 22.4 一次性驳回（罕见但致命）。

### 26.3 说明书充分公开

触发场景：本领域技术人员据说明书 + 公知常识能否实现方案；关键参数 / 算法 / 接口是否给出。

典型缺陷：

- 关键算法只给名称未给步骤或公式 → 高，`article=26.3`，`defect_type=逻辑`
- 关键参数取值范围未给且无示例 → 高，`article=26.3`，`defect_type=逻辑`
- 实施例数量不足以覆盖独权范围 → 中，`article=26.3`，`defect_type=逻辑`

严重度判定：是否会被审查员以 26.3 驳回或要求大幅补充。

### 26.4 权利要求清楚 / 支持

触发场景：权要措辞是否清楚、是否得到说明书支持。

典型缺陷：

- 独权使用功能性限定但说明书未给出可实现方式 → 高，`article=26.4`，`defect_type=逻辑`
- 独权技术特征措辞模糊（"较好地"、"显著"、"等"）→ 中，`article=26.4`，`defect_type=形式`
- 从权附加技术特征未在说明书展开 → 中，`article=26.4`，`defect_type=逻辑`
- **独权"实施例化"**：独权包含字节级结构 / 路径生成规则 / 文件描述符操作 / 同步刷盘步骤 / 单步内嵌"命中分支 + 未命中分支"等具象实现 → 高，`article=26.4`，`defect_type=逻辑`（同时触发"概括过窄不足以支持上位技术方案"）
- **并列独权与从权字面/语义复刻**：P2 独权与 P1 间接从权对同一组特征逐字或近逐字重写 → 高，`article=26.4`，`defect_type=逻辑`（同时与 02 重复条目联动）
- **跨权要实现冲突**：同一概念（如互斥保护、回校验、深拷贝时机）在不同权要中实现细节互斥或表述不一致 → 高，`article=26.4`，`defect_type=逻辑`（同时与 26.3 据以实施联动）

严重度判定：是否会被以 26.4 要求修改或缩限。

### 与既有方向边界

- 26.3 ⇄ 03 说明书支撑：03 看「实施例是否撑住权要」，26.3 看「本领域技术人员能否据以实施」；同根因由综合 subagent 去重，**两份产物均保留**。
- 26.4 ⇄ 02 权利要求：02 看「保护范围层次与独从权关系」，26.4 看「清楚 / 支持」；同根因由综合 subagent 去重。
- 22.3 ⇄ 01 气质审查：01 看「与对应类型锚样稿（CN113596424A 方法类 / CN117336591A 结构类，按权 1 判型选）对照的独权肥度 / 抽象层 / 细节落点 / 节奏 / 密度」，22.3 看「区别特征非显而易见性」；视角独立，原则上不去重。
- 22.2 / 22.4：direction-01 ~ direction-05 无对应法条合规口径，direction-06 独占。

### 严重度到既有 3 级映射

| 法条严重度 | 既有 `priority_hint` | 处置 |
|---|---|---|
| 高（审查员可直接驳回） | 高 | 阻断 Gate B；revision 必须修订 |
| 中（审查员会下通知书要求修改） | 中 | 用户逐条决策；revision 按用户决策修订 |
| 低（仅建议性 / 形式瑕疵） | 形式 | 入库；revision 可批量处理 |

注：`defect_type=形式` 主要落在 26.4 措辞类瑕疵；22.2/22.3/22.4 本质是逻辑缺陷，`defect_type=形式` 在这三条几乎不触发，是预期稀疏，不强求 5 法条各覆盖两种类型。

## 气质审查清单

气质审查 subagent 必读输入（按权 1 判型选锚样稿与起草侧骨架表）：

判型规则：
- 权 1 第一句以动词起（获取/根据/得到/确定/判断/获得...）→ 方法类 → 锚样稿 = CN113596424A
- 权 1 第一句以「一种 XX 装置/设备/模组/组件/系统」起，后接部件列表 → 结构类 → 锚样稿 = CN117336591A
- 无法判定 → 不进入气质审查，返回 stop-recommended

按判型选锚样稿与骨架表（只读匹配的那一份，不交叉读取）：

- 待审正式稿（drafts/markdown/<draft-name>.md，常驻必读）
- 方法类（待审稿命中方法类时）：
  - CN113596424A 原稿：`/root/.claude/skills/cn-patent-attorney-review/references/CN113596424A_动态范围映射的方法和装置-结构化整理版.md`
  - `../cn-patent-formal-drafting/references/method-claim-drafting.md`（§独权骨架 + §从权梯队 + §红线 + §权要句式库 + §实施方式句式库）
- 结构类（待审稿命中结构类时）：
  - CN117336591A 原稿：`/root/.claude/skills/cn-patent-attorney-review/references/CN117336591A_摄像头模组和电子设备.md`
  - `../cn-patent-formal-drafting/references/structural-claim-drafting.md`（§独权骨架 + §从权梯队 + §红线 + §权要句式库 + §实施方式句式库）

5 子项（每项独立扫描，单独输出 schema）：

### 独权肥度审查

检查点：独权是否含可下放的特征（参数公式 / 阈值具体数字 / 字段名 / 替代实现 / 连续性约束 / 步骤号 / 多分支条件展开 / 装置单元名）。对照 method-claim-drafting.md §红线 R1-R7 逐条扫描。

判定规则：动作数 > 6 → 高优先级；动作内嵌公式 / 变量定义 / 阈值 / 步骤号 / 装置单元名 → 高优先级；多分支条件展开 → 中优先级。

### 抽象层审查

检查点：权要 / 说明书是否绑定代码符号（函数名 / 变量名 / 文件名 / 类名 / 字段名 / 枚举常量名）、工程颗粒度词（"该函数 / 该字段 / 该消息 / 该接口"等）。对照 method-claim-drafting.md §红线 R4。

判定规则：独权出现代码符号 → 高优先级；说明书 / 实施方式过度依赖代码符号而无语义抽象 → 中优先级；首次出现括号辅助但后续未抽象 → 形式问题。

### 细节落点审查

检查点：每个细节是否落到正确层级（独权 / 从权 N / 实施例 / 分案）。对照 method-claim-drafting.md §从权梯队（A4/A5/A6/A7 句式对应的从权位置）+ §实施方式句式库（B1-B5 段落组织）。

判定规则：参数定义 / 公式 / 连续性约束在独权内 → 高优先级（应下放 A5/A6/A7 从权）；具体阈值在说明书但应在从权 → 中优先级；可选实施方式被写成独立实施例 → 形式问题。

### 节奏对照审查

检查点：与待审稿对应类型锚样稿对比独权部件 / 动作数、从权层级数、各句式分布。

实证基线（按判型选用）：

| 类型 | 锚样稿 | 独权基线 | 从权基线 | 配套保护 |
|---|---|---|---|---|
| 方法类 | CN113596424A | 5 动作 | 11 条（A4×1 + A5×4 + A6×2 + A7×3）| 装置镜像 12 条 |
| 结构类 | CN117336591A | 2 部件块 + 1 段装配关系约束句 | 13 条（S1×1 + S2×1 + S3×3 + S4×2 + S5×6）| 整机配套 1 条（S6）|

判定规则（按判型选用对应基线）：
- 方法类：独权动作数偏离 5 ±2 以上 → 中优先级；从权层级数偏离 11 ±50% → 中优先级；某 A 类句式完全缺失 → 形式问题
- 结构类：独权部件块数偏离 2-4 范围 → 中优先级；从权层级数偏离 13 ±50% → 中优先级；某 S 类句式完全缺失 → 形式问题

### 密度匹配审查

检查点：与待审稿对应类型锚样稿 §具体实施方式 密度对照。

- 方法类（对照 CN113596424A）：是否过度铺工程细节（伪代码 / 流程图节点引用 / 详细类设计 / API 签名）或反之过于抽象（缺少 B2 参数取值 / B3 计算示例 / B4 可选实施方式）
- 结构类（对照 CN117336591A）：是否过度铺装配工艺细节（具体 SMT 步骤 / 厂商工艺 / 装配次序号）或反之过于抽象（缺少 B2 参数取值 / B3 替代参数 / B4 第二实施方式 / 附图标号对应表）

扫描步骤（必做）：逐段标注实施方式段所属 B 类句式（B1 段落组织 / B2 参数取值 / B3 替代参数或计算示例 / B4 可选或第二实施方式 / B5 效果回扣），统计 5 类句式各自命中段数；缺失类按数量记录；不得凭整体印象判定"密度偏高 / 偏低"。

判定规则：
- 方法类：实施方式含伪代码 / 流程图节点引用 → 高优先级；B2/B3/B4/B5 五类句式中缺少 2 类以上 → 中优先级；段落组织违反 B1（用 S1/S2 步骤号或 1.2.3. 编号列表）→ 形式问题
- 结构类：实施方式含装配次序号（"S1 步骤""第一步""1. 2. 3."）→ 高优先级；缺少附图标号对应表 → 高优先级；B2/B3/B4/B5 五类句式中缺少 2 类以上 → 中优先级；段落组织违反 B1（用三级小标题切分自然段）→ 形式问题
