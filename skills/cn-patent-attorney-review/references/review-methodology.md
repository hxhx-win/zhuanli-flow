# 审稿发现写法

本文件只规定代理师审稿发现如何表达、分级和合并。审稿流程、子 agent 维度、Gate 和状态回写以 `../SKILL.md` 与 `../../cn-patent-domain-runtime/references/orchestration-philosophy.md § 审稿前风险与 Gate B/修订复核哲学` 为准。

## 单条发现格式

每条审稿发现应包含：

- 位置：权利要求、说明书章节、摘要、附图说明或导出契约。
- 问题：具体缺陷，不写泛泛判断。
- 风险：对保护范围、创造性、支撑充分性、清楚性或导出可用性的影响。
- 修改建议：可执行的修改方向。
- 是否需用户决策：需要选择、补证或授权时必须标出。

## 分级标准

- 高优先级：影响独立权利要求稳定性、区别特征表达、创造性论证、说明书支撑或 Gate A 主线一致性。
- 中优先级：影响从属权利要求层次、实施例充分性、公式/变量解释、技术效果链条或补证质量。
- 形式与术语：影响标题结构、术语一致性、编号、格式、内部章节残留、导出契约或附图交接完整性。

### 法条合规严重度映射

direction-06 子 agent 用法条原文严重度判定后，按下表映射到既有 3 级（与既有 `priority_hint` 一致，不另设 4 级）：

| 法条严重度 | 既有优先级 | 处置 |
|---|---|---|
| 高（审查员可直接驳回） | 高 | 阻断 Gate B；revision subagent 必须修订 |
| 中（审查员会下通知书要求修改） | 中 | 用户逐条决策；revision subagent 按用户决策修订 |
| 低（仅建议性 / 形式瑕疵） | 形式 | 入库；revision subagent 可批量处理 |

## 子 agent 发现合并

主 agent 汇总子 agent 发现时：

- 合并同一根因，不按子 agent 原始条数机械罗列。
- 同一问题跨多个章节出现时，归为一条问题并列出受影响位置。
- 子 agent 结论冲突时，列为“需要用户选择的事项”或由主 agent 给出取舍理由。
- 气质审查发现若涉及独权肥度 / 抽象层 / 细节落点 / 节奏对照 / 密度匹配 5 子项，按 `references/review-checklists.md § 气质审查清单` 中各子项判定规则定级；与 CN113596424A 实证基线（独权 5 动作 / 从权 11 条）明显偏离时列为高优先级。
- 创造性与区别特征一致性发现必须对照 prior-art 检索结论和 Gate A 确认主线，不得只写“创造性不够稳”。
- direction-06 法条合规与 02 权利要求 / 03 说明书支撑同根因时，**两份产物均保留**于 `reviews/attorney-review/` 子审查目录；综合稿合并为一条问题，列出受影响的法条 + 既有维度。
- direction-06 发现的 `defect_type=形式` 与 04 形式与证据同根因时，按 04 维度归类，但综合稿条目末尾标注「同涉 article=XX.X」便于追溯。

## 修改建议写法

修改建议必须能指导后续修订：

- 不要只写“加强说明”“完善权利要求”。
- 应指出要补哪类技术特征、放在哪个章节、用于支撑哪个权利要求或区别特征。
- 需要用户提供资料时，明确资料类型，例如实验数据、参数范围、对比结果、流程图或接口说明。

## 不要混淆的边界

- 代理师修改意见单独成文，不写进权利要求书或说明书正文。
- 用户反馈文件记录决策、补证、授权范围和本轮修订摘要，不直接代替修订稿。
- 子 agent 只返回发现，不直接改稿、写 review 文件或推进 Gate。
